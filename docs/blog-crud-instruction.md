# Blog CRUD - Backend Implementation Guide

This document outlines the requirements and API endpoints needed for the Blog Builder CRUD operations.

## Database Schema Suggestions

### Table: `blogs`
| Column | Type | Description |
| --- | --- | --- |
| `id` | INT (PK) | Unique identifier |
| `title` | VARCHAR(255) | Blog title (Required) |
| `slug` | VARCHAR(255) | SEO friendly URL slug (Unique) |
| `author` | VARCHAR(255) | Author name |
| `publishDate` | DATE | Date of publication |
| `status` | ENUM | 'draft', 'published', 'archived' |
| `coverImage` | TEXT/VARCHAR | URL of the cover image |
| `metaDescription` | TEXT | For SEO meta tags |
| `content` | LONGTEXT | The generated HTML content from the builder |
| `components_json` | LONGTEXT | JSON string of the raw builder components (Critical for Edit mode) |
| `created_at` | TIMESTAMP | Creation time |
| `updated_at` | TIMESTAMP | Last update time |

## API Endpoints

All endpoints should be prefixed with `admin/` and protected by authentication middleware.

### 1. List Blogs
- **Endpoint:** `GET /admin/blogs`
- **Query Params:** `page`, `search`
- **Response Format:**
```json
{
    "isExecute": "SUCCESS",
    "data": {
        "data": [...],
        "total": 100,
        "from": 1,
        "to": 10,
        "last_page": 10
    }
}
```

### 2. Get Single Blog
- **Endpoint:** `GET /admin/blogs/{id}`
- **Response Format:**
```json
{
    "isExecute": "SUCCESS",
    "data": {
        "id": 1,
        "title": "...",
        "content": "...",
        "components_json": "[...]",
        ...
    }
}
```

### 3. Create Blog
- **Endpoint:** `POST /admin/blogs`
- **Payload:**
```json
{
    "title": "...",
    "slug": "...",
    "author": "...",
    "publishDate": "YYYY-MM-DD",
    "status": "draft",
    "coverImage": "URL",
    "metaDescription": "...",
    "content": "HTML_STRING",
    "components_json": "JSON_STRING"
}
```
- **Response:** `{ "isExecute": "SUCCESS", "message": "Blog created" }`

### 4. Update Blog
- **Endpoint:** `POST /admin/blogs/update/{id}`
- **Payload:** Same as Create
- **Response:** `{ "isExecute": "SUCCESS", "message": "Blog updated" }`

### 5. Delete Blog
- **Endpoint:** `DELETE /admin/blogs/{id}`
- **Response:** `{ "isExecute": "SUCCESS", "message": "Blog deleted" }`

## Critical Implementation Notes

1.  **HTML Sanitization**: While the `content` is generated by the frontend, ensure the backend doesn't strip essential styling attributes used by the builder (e.g., `style="color: #...; background-color: #...;"`).
2.  **components_json**: DO NOT modify this field on the backend. It must store the exact JSON string sent by the frontend so the builder can reconstruct the editor state when the user returns to edit the blog.
3.  **Unique Slugs**: Ensure slugs are unique in the database to avoid routing issues on the public side.
4.  **Middleware**: Apply `auth:sanctum` and any `admin` role checks.
